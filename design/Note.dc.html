Home-cooked software, and why I stopped polishing

Most of the tools I use every day were built in an afternoon, for exactly one problem, and never shown to anyone. A script that turns a folder of screenshots into a dated note. A watcher that tells me when the library posts its sale dates. None of them would survive a code review, and none of them need to.

Robin Sloan called this home-cooked software: a meal for the people in your house, not a restaurant. The metaphor stuck because it explains the feeling when I finish one. It isn’t pride. It’s closer to being fed.

## what changed

I used to finish a tool and immediately start on a README, a settings file, a second user. That’s the moment it stopped being cooking. Now the rule is that a tool stays a single file until it has earned a second one by being used for a month.

$ ls tools/
library-sale-watch.py     # 61 lines, runs hourly
screenshots-to-notes.py   # 40 lines, runs nightly
letter-assembler.py       # 118 lines, runs fridays

Two of those build the weekly letter. The rest of the shelf is on the tools page, each with its last run.
